# Формат проекта

Каждый проект — папка `projects/<slug>/`:
```
projects/<slug>/
  project.json      ← все тексты и структура страницы
  img/*.jpg         ← скриншоты (1280×800, JPEG ~78%; телефон 390×844 @2x)
```
и строка `"<slug>"` в `projects/index.json` (порядок = порядок на главной).
Страница проекта открывается как `project.html?p=<slug>`. Пример — `projects/studio-booking/project.json`.

## project.json
| Поле | Обязательно | Что это |
|---|---|---|
| `slug` | да | совпадает с именем папки: `a-z`, `0-9`, `-` |
| `title`, `subtitle` | да | название и одна фраза о проекте (карточка на главной) |
| `cover` | да | путь к картинке карточки, например `img/home.jpg` |
| `status` | нет | `idea` · `in_progress` · `testing` · `deployed` · `done` · `paused` |
| `year`, `role`, `client_type` | нет | год, ваша роль, для какого бизнеса |
| `stack[]`, `tags[]` | нет | технологии; 2–4 тега для карточки |
| `links[]` | нет | `{ "label", "url" }` — только публичные ссылки (демо, сайт) |
| `hero` | нет | `headline` (слово в `*звёздочках*` выделяется цветом), `lead`, `facts[] {value,label}`, `image`, `phone`, `url` (подпись в адресной строке) |
| `flow` | нет | схема шагов: `no`, `title`, `lead`, `nav`, `steps[] {label,title,text}` |
| `chapters[]` | нет | главы по ролям/разделам: `id`, `no`, `title`, `nav` (короткое имя в оглавлении), `lead`, `screens[]` |
| `screens[]` | — | `id` (уникальный), `img`, `full` (картинка во весь рост, по клику), `url`, `title`, `roles[]`, `tag` (оранжевая метка: «деньги», «правила»…), `text`, `logic[]` (пункты «Бизнес-логика»), `logic_title` (другой заголовок списка) |
| `cards` | нет | `id`, `nav`, `no`, `title`, `lead`, `items[] {chip, rule:true/false, title, text}` |
| `gallery` | нет | `id`, `nav`, `no`, `title`, `lead`, `items[] {img, caption, phone:true/false}`, `steps[] {title,text}` |
| `table` | нет | `id`, `nav`, `no`, `title`, `lead`, `head[]`, `rows[][]` |
| `footnote` | нет | мелкий текст внизу (например «данные демонстрационные») |

## Правила
- Никаких секретов: паролей, токенов, IP серверов, адресов админок, реальных телефонов и имён клиентов.
- Скриншоты — только на демо-данных.
- Пишите от лица пользователя продукта: что человек делает и какое правило работает, без внутренних терминов.
- Перед публикацией: `node scripts/check.js` должен ответить `OK`.
